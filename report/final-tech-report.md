## 核心算法或策略

### 时序平滑算法方案

当前仓库中的平滑并不是“套一个统一滤波器”就结束，而是由 `src/gesture/temporal.py` 中的 `TemporalReducer` 组织成一套分层时序策略。代码中没有引入完整的 Kalman Filter、One Euro Filter 或 Savitzky-Golay 之类的通用滤波器；当前实现更偏向面向交互任务的工程化组合方案，目标是在 30 FPS 左右的单目手部跟踪条件下，同时兼顾稳定性、响应速度和可解释性。

第一层是基于指数平滑的坐标滤波。系统对 `index_tip`、`thumb_tip` 和 `wrist` 分别做一阶时序更新，形式上等价于 `previous + alpha * (current - previous)`，并为不同运动预设配置不同参数。`high`、`medium`、`low` 三组预设不仅控制 `xy` 与 `z` 方向的平滑系数，还同时控制位置死区、短时预测混合比例和丢失跟踪时的速度衰减系数。从实际行为看，`low` 预设更灵敏、跟手性更强，`high` 预设则更保守、更稳。

第二层是面向图像噪声特征的轴向差异化平滑。实现中没有把三个坐标轴等价处理，而是显式地区分横向、纵向和深度方向：`x` 方向使用更强抑制来压制横向扫动带来的抖动；`y` 方向会根据 `blur_level` 和瞬时位移自适应调整平滑强度，在模糊较高时变得更稳，在明确的竖直运动出现时保持较高响应；`z` 方向使用独立的平滑系数控制深度抖动。与此同时，位置死区用于直接吞掉微小噪声，避免目标在静止时出现细碎漂移。

第三层是短时失跟时的运动预测。当前实现采用的是带阻尼的常速度外推，而不是复杂状态空间估计：系统先根据最近两帧平滑后的位置计算速度，再在检测丢失时按 `prediction_lead` 和 `prediction_blend` 将该速度外推到 `index_tip`、`thumb_tip` 和 `wrist` 上，同时随丢帧数增加对速度做指数衰减。这样做的好处是参数少、延迟低、行为容易调试。在 `TEMPORAL_TRACKING_TEMPORARY_LOSS_FRAMES` 窗口内，系统仍可输出 `temporarily_lost` 或维持受控的 `tracked` 状态，而不是让目标立刻跳回未检测状态。

第四层是重新捕获后的平滑回接。当观测源从 `predicted` 或 `fallback` 回到 `detected` 时，系统不会立即完全相信新观测，而是先在预测轨迹和新检测结果之间进行数帧混合，并对单帧最大 `dx/dy` 做限幅。如果重新检测位置与预测位置偏差过大，还会进入更保守的 `reacquire_blend` 路径，主动降低融合权重。该设计直接解决了“重新识别成功但物体突然跳一下”的体验问题。

第五层是状态级平滑，也就是对“交互语义”而不是对“坐标值”做时序稳定。捏合判断并非只看当前指尖距离，而是把几何距离的高斯似然、先验状态以及外观匹配分数融合成 `pinch_score`，再通过进入阈值、释放阈值、确认帧数和释放保护机制实现滞回控制。对于快速移动、前向朝向或低质量帧，系统会刻意阻止过早释放，从而降低抓取过程中的误触发。旋转通道则采用另一种平滑思路：先把指尖中点的连续位移转换为等效角度增量，再通过门控计数、趋势抑制和离散槽位累积输出稳定的旋转步进，而不是直接输出高噪声的连续角度。

综合来看，当前平滑算法方案可以概括为“坐标级低通 + 质量感知修正 + 短时预测 + 回接混合 + 状态滞回”的组合式架构。它的优势是调参直观、调试信息完整、与交互状态机耦合紧密，适合当前项目这种实时交互型原型系统；代价是规则较多、参数之间存在耦合，后续如果系统升级到多手、多目标或更复杂的三维姿态估计，再考虑引入更统一的概率滤波框架会更合适。
